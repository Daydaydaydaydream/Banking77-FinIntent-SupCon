# 后续开发与求职交付规划

更新日期：2026-10-12。

## 1. 目标与现状

项目目标是回答不同训练标注预算下的模型选型问题，并验证 SupCon 与难负例加权的收益边界。项目完成不要求某种方法必须涨分。

已完成：数据准备和固定划分、三类基线、两阶段 SupCon 与 HN 实现、5 方法 × 4 设置 × 3 种子的 60 组运行、指标聚合及混淆分析。当前成果适合作为实验评估型简历项目。

尚未完成：严格控制训练流程的损失对照、完整效果与成本分析、面试材料和最小推理交付。下面的阶段是后续计划，不表示已实现；本次仅更新文档与报告口径。

## 2. P0：统一实验口径与文档

状态：已完成当前可核验产物复核，见 [ARTIFACT_AUDIT.md](ARTIFACT_AUDIT.md)。60 组指标内部一致；逐条预测与历史数据指纹缺失，已披露且不补造。

任务：

- 将 BERT 与两阶段 SupCon 称为训练方案比较，不宣称只改变损失函数。
- 区分训练标注预算与额外的 1,003 条有标签验证数据；说明 SetFit 与 BERT 使用不同 backbone。
- 核对 60 组运行的配置、状态、预测和指标是否对应，核查样本划分、重复文本披露及模型选择记录。
- 保留早期故障报告的历史身份，避免旧结论进入简历和当前报告。

验收：当前文档无互相冲突的状态描述；结果可由运行产物复算；完成一次产物一致性检查并记录结论。

## 3. P1：补受控实验，回答方法归因

状态：三组联合训练与 HN 实现修复已完成，71 项测试及三组真实 BERT smoke 通过；正式 36 组待确定 CPU/CUDA 环境后执行。详见 [CONTROLLED_EXPERIMENTS.md](CONTROLLED_EXPERIMENTS.md)。

建议新增三组：CE、CE + SupCon、CE + SupCon + HN。三组采用相同 BERT、分类头、类平衡采样、端到端训练流程和评估入口；分别隔离对比损失与 HN 的增量。原有两阶段方案继续保留，不覆盖旧运行。

实验要求：

- 固定数据划分、种子、最大长度、有效 batch size、优化器与更新步数预算；共同按验证 Macro-F1 选择 checkpoint，记录实际步数与耗时。
- 在验证集选择损失权重、温度与学习率，预先声明各组调参候选和预算，保存冻结配置。
- 先用 5-shot、seed 42 验证损失、梯度、正样本条件和保存加载；流程通过后扩展到 4 设置 × 3 种子，共 36 组新增正式运行。
- CE 控制组也使用同样采样，以免将采样收益混入损失收益。固定步数不等于固定计算成本，额外报告时间。
- 已有测试集结果已被查看；新增实验必须披露这一事实。新配置仍只能按验证集选择，冻结后统一测试，不把新增结果描述为从未查看过测试集的确认性研究。

验收：三组差异可由配置复核；报告配对 Macro-F1 差值、各 seed 方向、逐类指标和成本；负结果同样完成验收。若资源不足，明确缩小的设置范围，不宣称完成完整矩阵。

## 4. P2：完善结果解释与成本分析

状态：待开展；可先基于已有结果完成。

任务：

- 汇总效果、种子波动、实际训练时间和训练步数；比较前核对设备、精度和计时范围，条件不同则分别呈现。
- 分别分析 BERT→SupCon 与 SupCon→HN 的 29 个预定义类别对，补齐各设置下的同口径展示。
- 选取 6–10 条真实误判文本，展示真值、预测和业务语义边界；注明案例选择规则，覆盖改善、恶化和共同失败，不用个案替代总体统计。
- 整理 float16 异常的证据、排查过程及修复验证。区分已有日志证据与尚未证实的解释，不将故障修复涨分写成算法增益。
- 对新增实验报告同样的分析，保留不确定性；三个种子不足以支持普遍性结论。

验收：主结果表、成本表、混淆分析和文本案例均有产物来源；结论明确适用设置与局限。

## 5. P3：形成简历与面试交付

状态：初版说明已建立，最终材料待收尾。

任务：

- 完成一页项目概览：业务问题、实验设计、核心结果、局限和可复现入口。
- 根据最终结果更新三条简历描述，只写实际完成且能解释的工作。
- 准备 3 分钟项目讲解，以及 Macro-F1、数据泄漏、few-shot 预算、训练故障、SupCon 正负样本和负结果的回答。
- 在干净环境验证文档中的最小复现流程，记录依赖、模型获取方式、硬件和预期输出；训练指标允许合理数值波动。

验收：第三方能沿文档定位结果与配置；候选人能够解释方法选择、实验不足和自己的实际贡献。

## 6. P4：最小推理演示（算法工程岗位可选）

状态：待开展，不属于现有成果。

任务：基于验证结果选择并保存模型，提供单条/批量英文输入、标签及 Top-k 分数输出，验证模型重载、标签映射、空输入与长文本行为。分数未经校准时不描述为可靠概率。若测延迟，注明设备、batch size、预热及计时范围。

验收：模型加载后预测可复现，有可运行命令和若干演示输入。公开展示仅使用公开数据或人工构造文本，不宣称已上线银行系统。

## 7. 执行顺序与完成标准

优先顺序：P0 复核 → P1 受控实验 → P2 完整分析 → P3 求职材料；P2 的已有结果分析可提前进行，P4 按岗位需要补充。

实验评估型交付至少完成 P0、P2、P3，并如实保留归因局限；若要强调算法改进或损失设计贡献，还应完成 P1。工程型交付进一步完成 P4。

暂不扩展开放集识别、主动学习、更多大模型、Docker 和监控，除非它们服务于新增的明确目标。不得为追求正结果反复按测试分数调参。
