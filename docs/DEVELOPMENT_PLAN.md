# 后续开发与求职交付规划

更新日期：2026-10-27。历史检查见 [项目状态检查](STATUS_2026-10-26.md)，本次交付和目标机器操作见 [WSL 运行手册](WSL_RUNBOOK.md)。

## 1. 目标与现状

项目目标是回答不同训练标注预算下的模型选型问题，并验证 SupCon 与难负例加权的收益边界。项目完成不要求某种方法必须涨分。结合 Applied AI Engineer 职业目标，本项目定位为实验评估辅助作品，优先完成 5-shot 的 9 组正式实验、自动报告和最小推理，再将主要精力转回医疗软件 Agent。

已完成：数据准备和固定划分、三类基线、两阶段 SupCon、5 方法 × 4 设置 × 3 种子的 60 组历史运行、指标聚合及混淆分析。HN 已修复，但历史 12 组 HN 运行不构成修复后方法的有效证据。当前成果适合作为实验评估型简历项目。

尚未完成：受控正式实验、修复后 HN 的效果验证、完整效果与成本分析、最终面试材料和最小推理交付。PathPT 启发的文本语义提示方案仅完成讨论，尚无实现和实验。下面按优先级列出任务与验收条件；本次检查未启动新的长时间训练。

## 2. P0：统一实验口径与文档

状态：已完成当前可核验产物复核，见 [ARTIFACT_AUDIT.md](ARTIFACT_AUDIT.md)。60 组指标内部一致；逐条预测与历史数据指纹缺失，已披露且不补造。

任务：

- 将 BERT 与两阶段 SupCon 称为训练方案比较，不宣称只改变损失函数。
- 区分训练标注预算与额外的 1,003 条有标签验证数据；说明 SetFit 与 BERT 使用不同 backbone。
- 核对 60 组运行的配置、状态、预测和指标是否对应，核查样本划分、重复文本披露及模型选择记录。
- 保留早期故障报告的历史身份，避免旧结论进入简历和当前报告。

验收：当前文档无互相冲突的状态描述；结果可由运行产物复算；完成一次产物一致性检查并记录结论。

## 3. P1：补受控实验，回答方法归因

状态：三组联合训练与 HN 实现修复已完成，71 项测试及三组真实 BERT smoke 通过；正式实验待用户在 RTX 5060 Ti 16GB / WSL2 执行。已新增 GPU v2 配置、预检、运行脚本和严格结果报告；优先 5-shot 共 9 组，其余 27 组可选。开发机 CUDA/MPS 不可用，不把 CPU 验证视为 GPU 验证。详见 [CONTROLLED_EXPERIMENTS.md](CONTROLLED_EXPERIMENTS.md)。

已实现三组：CE、CE + SupCon、CE + SupCon + HN；正式结果尚未生成。三组采用相同 BERT、分类头、类平衡采样、端到端训练流程和评估入口；分别隔离对比损失与 HN 的增量。原有两阶段方案继续保留，不覆盖旧运行。

实验要求：

- 固定数据划分、种子、最大长度、有效 batch size、优化器与更新步数预算；共同按验证 Macro-F1 选择 checkpoint，记录实际步数与耗时。
- 当前 controlled_v1 为预先声明的固定协议，可先按它执行，结论限定于该配置。如需调参，在验证集选择损失权重、温度与学习率，预先声明各组候选和预算，另存协议版本，避免混合汇总。
- 先用 5-shot、seed 42 验证损失、梯度、正样本条件和保存加载；流程通过后扩展到 4 设置 × 3 种子，共 36 组新增正式运行。
- CE 控制组也使用同样采样，以免将采样收益混入损失收益。固定步数不等于固定计算成本，额外报告时间。
- 已有测试集结果已被查看；新增实验必须披露这一事实。新配置仍只能按验证集选择，冻结后统一测试，不把新增结果描述为从未查看过测试集的确认性研究。

验收：三组差异可由配置复核；报告配对 Macro-F1 差值、各 seed 方向、逐类指标和成本；负结果同样完成验收。若资源不足，明确缩小的设置范围，不宣称完成完整矩阵。

## 4. P2：完善结果解释与成本分析

任务：

- 汇总效果、种子波动、实际训练时间和训练步数；比较前核对设备、精度和计时范围，条件不同则分别呈现。
- 分别分析 BERT→SupCon 与 SupCon→HN 的 29 个预定义类别对，补齐各设置下的同口径展示。
- 新增正式运行保存逐条预测后，选取 6–10 条真实误判文本，展示真值、预测和业务语义边界；注明案例选择规则，覆盖改善、恶化和共同失败，不用个案替代总体统计。历史 60 组缺逐条预测，不能从混淆矩阵补造；重新推理必须有对应选中权重，否则需明确作为新运行。
- 整理 float16 异常的证据、排查过程及修复验证。区分已有日志证据与尚未证实的解释，不将故障修复涨分写成算法增益。
- 对新增实验报告同样的分析，保留不确定性；三个种子不足以支持普遍性结论。

验收：主结果表、成本表、混淆分析和文本案例均有产物来源；结论明确适用设置与局限。

## 6. P4：最小推理演示（算法工程岗位可选）

状态：离线推理入口已实现，支持单条/批量、Top-k、空输入拒绝、长文本截断标记、模型文件校验及 CPU/CUDA。小型真实 BERT 集成测试通过；正式选中模型等待用户 GPU 运行后产生。

任务：基于验证结果选择并保存模型，提供单条/批量英文输入、标签及 Top-k 分数输出，验证模型重载、标签映射、空输入与长文本行为。分数未经校准时不描述为可靠概率。若测延迟，注明设备、batch size、预热及计时范围。

验收：模型加载后预测可复现，有可运行命令和若干演示输入。公开展示仅使用公开数据或人工构造文本，不宣称已上线银行系统。

## 7. P5：PathPT 启发的文本语义提示实验

状态：已讨论迁移方向，未实现、未训练。它是独立探索，不阻塞现有项目交付，也不称为原版 PathPT 的直接复现。参考：[PathPT 原论文方法](https://arxiv.org/html/2508.15904v1#S4.SS3)。

研究问题：5-shot 下，类别语义和可学习提示能否改善相近意图的区分？首版使用现有 all-MiniLM-L6-v2，冻结文本编码器；暂不迁移二维空间聚合及局部伪标签，不与 SupCon/HN 同时叠加。

任务与顺序：

1. 编写 77 类英文意图描述及语义边界，依据标签定义和训练数据固定版本、来源与哈希，不使用测试误判反向修改描述。描述属于额外人工语义信息，报告时披露。
2. 实现同一 backbone 的三组对照：冻结编码器 + 线性头；冻结编码器 + 固定描述的相似度分类；冻结编码器 + 可学习提示的描述相似度分类。固定描述组不训练，学习组共享训练数据及验证选择规则，分别记录计算成本。
3. 提示先采用类别间共享的少量可学习上下文向量，具体长度和学习率在预先声明的验证预算内选择。确认句向量池化、归一化、掩码正确；编码器权重冻结但提示分支保留梯度，不能将整条提示编码路径置于无梯度模式。
4. 先验证提示梯度非零、编码器不更新、固定提示可复现、保存重载预测一致；再运行 5-shot × seeds 42/43/44，即三组共 9 次评估。固定描述组若没有随机性，三个配对位置会重复相同预测，不将重复运行解释为独立稳定性证据。
5. 输出 Macro-F1、逐种子配对差值、29 个预定义混淆类别对、训练参数量与耗时；与已有 SetFit/BERT 比较时注明 backbone 和协议差异。

验收：固定描述组判断类别语义的价值，可学习提示组判断额外训练的价值。若收益方向一致且成本可接受，再扩展到 10/20-shot；否则记录负结果并结束该分支，不为追求涨分叠加模块。已有测试结果已查看，新增探索如实披露，配置仍只依据验证集选择。

## 8. 执行顺序与完成标准

优先顺序：P0 状态纠偏（本次完成）→ P1 受控实验 → P2 完整分析 → P3 求职材料。P2 已有结果的成本盘点可提前开展，P4 按岗位需要补充，P5 作为独立探索。

下一批可执行工作：

- 首先在用户的 RTX 5060 Ti 16GB / WSL2 上完成 prepare → GPU smoke → 5-shot 三方法 × 三 seeds 共 9 组。使用 controlled_gpu_v2.json，保留完整模型、预测、指纹、显存和耗时。
- 该批通过产物复核、生成报告和推理演示后即可收尾求职版本，范围明确标为 5-shot。10-shot、20-shot、full 的其余 27 组仅按后续需求扩展。
- 利用新增结果补成本表与真实案例，形成一页概览、3 分钟讲解及干净环境最小复现记录。
- P5 暂缓，不作为求职版本验收条件；主项目开发优先于扩展新算法。

实验评估型交付至少完成 P0、P2、P3，并如实保留归因局限；若要强调算法改进或损失设计贡献，还应完成 P1。工程型交付进一步完成 P4。

暂不扩展开放集识别、主动学习、更多大模型、Docker 和监控，除非它们服务于新增的明确目标。不得为追求正结果反复按测试分数调参。
