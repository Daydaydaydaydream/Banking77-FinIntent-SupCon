# 基线对照补充报告（BERT / SetFit / TF-IDF）

生成：2026-10-27，仅汇总**已有**产物，未重新训练、未重新推理。
本文件补充 REPORT.md：主报告只统计受控 3 臂矩阵（9 组），本文补上基线矩阵（60 组）并说明两套协议的关系。

## 1. 两套矩阵分别是什么

| | A 基线矩阵 | B 受控矩阵 |
|---|---|---|
| 方法 | tfidf_svm、setfit、bert、supcon、supcon_hn | ce、ce_supcon、ce_supcon_hn |
| 设置 | 5/10/20shot + full | 仅 5shot |
| 组数 | 60（20 组合 × 3 seeds） | 9（3 组合 × 3 seeds） |
| 训练配方 | 各方法独立调好的方案；BERT 全参数微调（few-shot ≥300 步，早停）；旧 SupCon 为对比训练后冻结编码器只训分类头；SetFit 用 all-MiniLM-L6-v2 | 同一编码器 BERT-base、同一 batch、同一 300 步，**只改损失函数** |
| 目的 | 回答「这个任务上哪类方案强」 | 回答「损失函数本身的增量」 |
| 产物 | outputs/runs/<method>/<setting>/seed<seed>/、outputs/results/ | outputs/job_ready_gpu_v2_retry/ |

因此 A 与 B 的绝对值**不能逐行直接相减**：编码器不同（SetFit 不是 BERT）、训练预算不同、旧 SupCon 还冻结了编码器。

## 7. 结论

1. **少样本（5-shot）里 SetFit 最强**，BERT 微调次之，TF-IDF 最弱；受控矩阵的 CE/SupCon 与 BERT 基线处于同一档（约 0.68–0.70）。
2. **SupCon 的增量在受控协议下真实存在但不大**：+0.0182（3/3 种子为正），且 CE 的种子波动明显更大（std 0.0112 vs 0.0050），均值差有一部分来自方差收缩。
3. **硬负样本（HN）没有增益**：受控矩阵 +0.0005（2/3 为正，seed44 为负）；旧矩阵 −0.0002。两套证据一致。
4. **样本量上去后格局反转**：full 设置下 BERT/SupCon 达到 0.92 以上，显著超过 SetFit（0.8768）与 TF-IDF（0.8879）；SetFit 的优势只在极少样本时成立。
5. 早期报告「SetFit 是最强少样本基线」建立在 BERT float16 塌缩之上；修正后该结论**只在 5-shot 成立**，10/20-shot 与 full 均被 BERT 反超，所以作为整体结论不成立（与 README 的历史更正一致）。

## 9. 局限

- 每个（方法, 设置）只有 3 个种子，均值差与标准差不支持强统计结论。
- 矩阵 A 的绝对值来自 2026-10-11 的代码与环境；矩阵 B 为当前代码重跑，两者共享同一数据划分与模型快照，但**耗时不可跨会话比较**（GPU 时钟/占用不同）。
- SetFit 与 BERT 的差异同时包含方法与编码器两个变量，不能单独归因。
- 测试集只用于最终评估，未参与任何超参数或 checkpoint 选择。
